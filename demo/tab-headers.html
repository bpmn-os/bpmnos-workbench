A mock: the bodies are stand-in rows and nothing here does anything. What is drawn faithfully is the band at the head of each column, in the packages' own stylesheets, at the default column width of 260 px. Every band names its tab on a line of its own above what governs the list, so the head of a column reads as a header rather than as a strip of controls. The band is bjs-tab-header, a fixed 64 px whose content is centred; two lines fit it, but only once its padding comes down from 16 px to 10, since 16 above and below leaves 32 px and two lines want about 38.

Properties has no band, drawing its own header inside the tab, which is the band the panel's header was measured against. Issues carries its three severities on one line rather than three, without counts, with a severity that has none shown and disabled rather than dropped. Tokens, Messages, Sequences and Decisions each carry the same all / selected-tokens filter they carry today, lifted out of the list so it stays while the list scrolls. The input stands to the right of everything a run produces: the instance table and one column per lookup the model references, each naming under its own name the file it was read from, as the properties panel names an element and its identifier beneath it. A lookup always names one; the instance table is the one that may have none, and then says so rather than saying nothing. What Sequences keeps is not in its band: a name, a filter and a switch are three lines, and the band holds two, so the switch heads the list instead, which is where a setting belongs rather than beside the thing that says what is shown. The Tokens tab shows no Input entry, the input leaving it for columns of its own.

A band clips rather than wraps, so a column narrowed below the default loses the last word and then the last mark; each severity carries a title, so hovering still says which it is.
